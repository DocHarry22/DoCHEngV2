## Persistent state and backups

The default production directory is the hosting user's `$HOME/.local/share/docheng-platform`, outside the replaceable deployment tree. Set `DOCHENG_DATA_DIR` to override it with an absolute persistent path. The database, media and release files must never be under `public_html`, the repository or `.next`.

`GET /api/health` reports database readiness and whether mail is configured without exposing paths, users, tokens or secrets. Verify it after deployment and after a restart. Create an account and ticket, restart the application, and confirm both remain accessible before accepting customer data at scale.

On the hosting account, `node tools/platform-admin.mjs backup /absolute/private/backup.sqlite` creates a consistent SQLite backup. Back up the media and releases directories as well, restrict backup access, encrypt off-site copies, and test restoration to a separate directory. A copied live SQLite file without its WAL is not a reliable backup. Configure the actual backup schedule before commercial activation; the repository does not claim an unconfigured backup service exists.

## First administrator

The owner must create their own account and verify their mailbox. Configure `DOCHENG_BOOTSTRAP_ADMIN_EMAIL` to the explicitly authorized email; consuming its verification link grants the first administrator role only when no administrator exists. No browser field can select a role. Remove that bootstrap setting after assignment.

Alternatively run `node tools/platform-admin.mjs grant-admin EMAIL` on the hosting account. It requires an existing verified, enabled account and creates an audit entry. There is no unauthenticated web bootstrap endpoint or shared administrator password.

## Transactional email

Hostinger Mail integration uses `HOSTINGER_MAIL_TOKEN` and `HOSTINGER_MAILBOX_ID`. Claim an eligible included email plan in hPanel first, create a dedicated DoCHEng mailbox, verify its MX/SPF/DKIM/DMARC configuration, then create a token scoped to that mailbox only. The API sends via its documented `/api/v1/mailboxes/{id}/send` endpoint and accepts only its successful HTTP 204 response. Secrets belong in Hostinger environment settings. The fallback Resend integration requires `RESEND_API_KEY` and a verified `DOCHENG_MAIL_FROM`.

The owner chose **included free email only**. Do not purchase a plan, enable paid renewal, reuse a sister brand's mailbox, or claim free-plan eligibility from the existence of a web hosting plan alone. Free plans may be time-limited; review the actual expiry and renewal settings in hPanel before enabling mail.

Tickets and confirmation messages persist even when the provider is unavailable. The UI reports queued messages. Administrators can retry queued mail in `/admin`. `sending` messages after a process failure require operator reconciliation against provider delivery logs before resetting them to queued; Hostinger's send API does not provide the Resend idempotency guarantee, so blind retries can duplicate messages. Expired verification/reset links must be regenerated by their account owner.

## Product publication and downloads

Base catalogue entries are the owner's named products, reviewed against public deployment/release evidence. Discovery does not automatically publish new repositories. Draft updates preserve the last approved publication. Review the original assets, descriptions, visibility and link identity, then explicitly approve publication. Withdrawals remove the public record while retaining the audit trail.

Uploaded media is private until referenced by an approved publication. Installers are streamed to private storage, bounded to 100 MB, checked for a plausible file signature and hashed twice. File signatures and checksums do not prove safety or publisher authenticity. Stable publication also requires the operator's installation-test and publisher-review attestations. Paid and account downloads enforce verified server sessions; paid downloads additionally require a current entitlement.

The publicly available Apologia Android 1.0.3 APK is an externally published **preview**. Its downloaded bytes match the published SHA-256 value; installation and signing have not been independently accepted. No core Desk, Resume or Compass native installer is advertised.

## Commercial activation gates

Billing stays inactive. The Paystack adapter accepts only test keys, explicit approved test offers and a separate licence secret. Provider verification must match the stored amount, ZAR currency, reference, verified account email and test environment before fulfilment. Browser redirects never grant access.

Existing prices remain proposals. The test receipt is clearly marked as a test receipt and is not a VAT tax invoice. Confirm business identity, VAT registration/treatment, final product prices, refund/cancellation terms, provider onboarding, recurring-payment acceptance tests and backups before any separate commercial release. No raw card information is collected. Live keys are deliberately rejected by this release.

## Security checks and rollback

Run lint, typecheck, unit/security tests, production dependency audit, production build and Playwright regression tests. Newer development tooling currently inherits an unpatched `braces` advisory through Next's ESLint plugin; do not run lint on untrusted glob patterns. Production dependencies are audited separately; do not downgrade the framework with `npm audit fix --force`.

Keep the previous completed Hostinger build and Git commit available. Roll back code through the same existing Git deployment; do not delete the persistent data directory. Database schema additions are additive. Before a schema-changing release, create and verify a consistent backup. Masked environment-variable responses cannot restore secret values: preserve the real values in the operator's secret manager before any full-set replacement.
