# Guided product editor

Open `/admin` with a verified administrator account. Choose an application under **Guided product editor**, or select **Add an application**.

1. Complete the name, descriptions, audience, key features, category and supported platforms. The new page address is suggested from the name and becomes fixed after the first save. New applications start as internal drafts.
2. Choose release status and visibility. Add a pricing description, documentation and support links. Pricing is descriptive; publication does not activate payments.
3. Upload a logo and screenshots. Uploads attach to the selected form automatically. Add captions, move screenshots up or remove them. PNG, JPEG and WebP are supported, up to 5 MB each and 12 screenshots per product.
4. Select **Save draft**. The preview updates while editing; the public page changes only after publication. Complete required fields before saving.
5. For live or beta products, enter the public HTTPS launch address and select **Verify launch URL** after saving. A changed launch address must be verified before publication. An entry-page check does not establish full application readiness.
6. Expand **Upload a release file** to attach a Windows or Android release to the saved product. The product is selected automatically. Provide a version, channel, requirements and notes. Stable releases require installation and publisher review. Uploads remain subject to server validation and explicit publication.
7. Review the preview, choose Public visibility, save changes, tick the publication approval checkbox and select **Approve and publish**. **Withdraw publication** removes the public listing while retaining its draft.

Changing product, starting another application or reloading a saved draft prompts before discarding unsaved edits. Closing or reloading the browser also warns about unsaved work. If another editor updates the same draft, saving is rejected and your form values remain available. Reload the saved draft only after deciding which edits to keep.

Support tickets, customer access, licences, email retries, reports and private repository references remain below the editor. Every operation uses authenticated server APIs. Client fields cannot manufacture launch evidence or replace release checksums.
